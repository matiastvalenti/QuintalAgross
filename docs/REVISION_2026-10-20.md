# Quintal Agross — Primera mejora técnica

Fecha: 20/10/2026. Base: archivo QuintalAgross_Back(1).rar recibido.

## Alcance

Esta entrega estabiliza la instalación y la configuración. No es una auditoría completa ni una aprobación para operar en producción. Se conservaron los circuitos y modelos contables existentes.

## Cambios

- backend/requirements.txt: recupera el manifiesto que estaba en logs y agrega dependencias que el código importa: python-jose, passlib y pypdf.
- backend/requirements-dev.txt: separa las herramientas de prueba.
- backend/app/core/config.py: busca el .env en backend, independientemente de dónde se invoque Python.
- backend/app/main.py: resuelve las carpetas de archivos estáticos desde la ubicación del código.
- backend/start_back.bat y backend/scripts/start_backend.bat: eliminan la ruta personal fija; usan el entorno .venv si existe y arrancan desde backend.
- frontend/src/config.js: permite configurar VITE_API_URL, conserva localhost como valor predeterminado y elimina barras finales.
- Plantillas .env.example y .gitignore: permiten documentar la configuración sin incluir claves reales.
- checks/test_bootstrap.py: verifica configuración, importación, health y archivos estáticos en una copia temporal, sin ejecutar migraciones ni alertas.
- README.md, TASKS.md y TASKS_STATE.json: documentan instalación, verificaciones y pendientes.

2. backend/app/main.py devuelve trazas internas en respuestas de error y tiene CORS abierto. Revisarlo antes de publicar.
3. La compilación avisa que el paquete principal supera 2,6 MB sin comprimir y que SalesApplicationsPage mezcla importación estática y dinámica. Revisar carga diferida por módulo.
4. El tablero previo marca muchas funciones como terminadas, pero no demuestra su validación funcional. No se modificaron retroactivamente esos estados.
5. Hay varias bases en la carpeta. El valor predeterminado del código es sql_app_v2.db; confirmar cuál se usa realmente y si contiene datos reales.
6. La prueba de salud solo confirma respuesta HTTP; no verifica integridad contable ni disponibilidad de la base.

## Aplicar esta actualización

Este ZIP contiene solo los archivos nuevos o modificados, no el proyecto completo.

1. Cerrar el backend y el frontend. Hacer una copia completa de la carpeta actual, incluidas bases, .env y uploads.
2. Extraer el ZIP y copiar el contenido de QuintalAgross_Back sobre la carpeta del proyecto recibido, respetando las rutas. Si editaste esos archivos después de enviar el RAR, comparar antes de reemplazar.
3. Mantener los .env existentes. Las plantillas .env.example son para instalaciones nuevas o para consultar opciones.
4. En backend, activar el entorno e instalar requirements.txt. Para pruebas, instalar requirements-dev.txt.
5. En frontend, ejecutar npm ci y npm run build. Configurar VITE_API_URL solo si el servidor está en otra dirección.
6. Para las verificaciones aisladas: ejecutar python -m pytest checks/ -q desde la raíz y npm test -- --run desde frontend.
7. Probar el arranque en una copia antes de usar datos reales: las migraciones automáticas originales siguen activas.

El archivo CAMBIOS.patch permite revisar exactamente las diferencias respecto de los archivos adjuntos. No incluye bases, credenciales, dependencias instaladas ni historial Git.
